## 2026-07-24 — Этап 1 (каркас) СДЕЛАН

### Откуда проект
До этого был полу-ручной MVP `~/projects/kotlowoi/traff/`: 6 файлов на stdlib-Python,
SQLite, статическая витрина `out/dashboard.html` с демо-цифрами из `seed.py`. Собирался под
ответы Артура от 23.07: «авто-постинг не нужен, нужен MVP с полупсевдорезультатами для
продажи МОИМ заказчикам».

24.07 Артур прислал пакет правок (TGTrack, автосбор метрик из ЛК Дзена и vc.ru, разделение
форматов, Вордстат, живой дашборд, задел на amoCRM). Это меняет класс задачи, поэтому
собран отдельный проект `~/projects/traff`. **Старый каталог не тронут** — он остаётся
референсом (контент-ДНК, вёрстка витрины, расчёты воронки).

### Что в правках Артура технически неверно (проверено, учтено)
1. `t.me/КАНАЛ?start=utm_…` — `?start=` понимают **только боты**, у канала параметр
   игнорируется. Правильно: именованная инвайт-ссылка (`createChatInviteLink`, `name` ≤ 32).
2. «Запрашивает у Telegram Bot API список новых подписчиков» — **такого метода нет**.
   Только апдейт `chat_member` (бот админом, `allowed_updates`), то есть постоянно
   работающий процесс: событие приходит в реальном времени, пропустил — потеряно.
3. **API TGTrack эту дыру не закрывает**: все три метода (`on_telegram_webhook`,
   `send_reach_goal`, `get_user_info`) требуют, чтобы `user_id` мы уже знали. Выгрузки
   «дай подписчиков за период» нет. Значит свой бот-слушатель нужен в любом случае, а раз
   он есть — `invite_link.name` из апдейта даёт атрибуцию напрямую, без TGTrack. TGTrack
   остаётся для MAX и для офлайн-конверсий в Директ.
4. Вордстат «headless + обход капчи» — не нужен: у Яндекса с 2025 есть **официальный
   Wordstat API**, бесплатный, по заявке; у Артура есть Директ-аккаунт.
5. Парсинг ЛК Дзена роботом рискованнее автопостинга, от которого отказались: Дзен-аккаунт =
   Яндекс-аккаунт (почта + монетизация). Решено: сначала импорт выгрузки и ручной ввод.
6. «CTR статьи» = переходы/показы — Telegram кликов не отдаёт вообще. Решается своим
   редиректом `/r/<code>` (этап 2).

### Решения (согласованы с Максимом)
- **Мультиарендность**: строим на одного арендатора, но `tenant_id` заложен во все таблицы
  данных — переход в SaaS не потребует миграции данных.
- **Стек**: Python-моно — FastAPI + Postgres + SQLAlchemy + Alembic + Jinja. Ядро генератора
  переезжает из MVP 1:1, Playwright и aiogram (этапы 2–3) тоже родные для Python.
- **Метрики площадок**: импорт файла и ручной ввод; Playwright — только по итогам разведки.

### Сделано
- Скелет: `docker-compose` (Postgres на **5436**), Dockerfile, `.env.example`, конфиг на
  pydantic-settings, venv.
- 13 таблиц + миграция Alembic. Цикл `upgrade → downgrade → upgrade` проверен и покрыт тестом.
- Ядро: перенесены `slugify`, `strip_long_dashes`, `md_to_html`, промпт с few-shot,
  шаблон-фолбэк; контент-ДНК Артура (голос, 10 кейсов, 2 поста-эталона, темник) переехала
  из `knowledge.py` в БД.
- 4 формата площадок (Telegram 4096 / MAX 3979 / Dzen 2000–4000 / vc.ru 2500–5000 +
  подзаголовок отдельным полем) и пост-валидатор: длина, плотность ключей 2–3 %,
  длинные тире, эмодзи-хайп, штампы, наличие CTA и хэштегов.
- Ключевые слова: вставка списком и загрузка CSV (`фраза`, `фраза;1200`, `фраза,1200`,
  таб), заголовки таблиц отбрасываются, дубли схлопываются.
- Веб: вход, страница проекта (каналы, голос, кейсы, ключи), генерация с выбором площадки
  и ключей, список статей, страница статьи с кнопками «Скопировать для …» (HTML для
  Дзена и vc.ru, Markdown для Telegram и MAX), отметка публикации.
- **46 тестов**, все зелёные. Сквозной сценарий проверен вживую curl-ом: вход → настройка
  каналов → импорт ключей → генерация под vc.ru и Telegram → страница статьи с UTM в CTA →
  отметка публикации. Изоляция арендаторов проверена (чужой проект и чужая статья → 404).

### Грабли этого этапа
- **`strip_long_dashes` из MVP склеивал абзацы**: шаблон `\s+[—–]\s+` захватывал перенос
  строки, и тире в начале строки превращало два абзаца в один через запятую. Починено:
  сначала снимаем тире в начале строки, потом внутристрочные, и только по горизонтальным
  пробелам (`[^\S\n]`).
- **Двойной вызов модели**: первый вариант роутера генерировал текст дважды, чтобы получить
  слаг для UTM. Исправлено функцией `generator.attach_cta` — ссылки дописываются к готовому
  тексту.
- **Alembic `env.py` перетирал URL** из настроек, из-за чего тест миграций пошёл бы в боевую
  БД. Теперь внешний URL (например, тестовый) имеет приоритет.
- **`expire_on_commit=False` в тестовой фикстуре**: после `seed_project` связи `project.cases`
  оставались пустыми в кэше сессии — добавлен `expire_all()`. В бою этого нет: сессия живёт
  один запрос.
- Артефакты проверки curl-ом (не дефекты кода): многострочное значение в `-F` обрезается,
  `;` внутри `-F` трактуется как разделитель параметров.

## 2026-07-24 — Этап 2 (трекинг подписок) СДЕЛАН в коде, ждёт ключей

Ответов Артура нет, поэтому весь этап написан так, чтобы включаться от наличия ключей, а
проверяться — на моках и фикстурах. Без токена бота система работает как раньше: прямые
ссылки с UTM, просто без атрибуции подписок.

### Как устроена атрибуция
Каждая статья получает свою **именованную пригласительную ссылку** в канал. Имя ссылки
начинается с 8-символьного кода трекинг-ссылки; Telegram присылает это имя в апдейте
`chat_member`, по нему находится статья. В тексте статьи стоит наш редирект `/r/<code>` —
только так считаются переходы, Telegram кликов не отдаёт. Полная схема, ограничения и
таблица решений — `_local_docs/internal/architecture/tracking.md`.

### Сделано
- Клиент Bot API (`getMe`, `createChatInviteLink`, `revokeChatInviteLink`) с превращением
  сетевых сбоев и `ok:false` в доменную ошибку.
- Создание трекинг-ссылок при генерации (Telegram / MAX / сайт), CTA собирается из них,
  мягкая деградация на прямые ссылки без токена или без прав бота.
- Редирект `/r/<code>` со счётчиком; отозванная ссылка ведёт по назначению, но клик не растит.
- Бот-слушатель на aiogram (long-polling — не нужен домен и HTTPS). Логика вынесена в
  `services/subscribers.py` и не зависит от aiogram.
- Клиент TGTrack (Telegram и MAX) и добор меток по уже известным подписчикам, журнал
  прогонов в `job_runs`.
- CLI: `check-bot` (проверить токен и доступ к каналу до подключения), `tgtrack-sync`.
- В интерфейсе: блок «Трекинг» на странице статьи и колонки «Переходы»/«Подписки» в списке.
- **83 теста** (было 46).

### Грабли этапа
- **Код в имени пригласительной ссылки не совпадал с кодом в базе**: в первой версии
  `create_tracking_links` код генерировался дважды. Атрибуция бы молча не работала —
  теперь инвариант закрыт тестом «по коду из имени находится та же ссылка».
- **`JobRun.tenant_id` был обязательным**, а опрос TGTrack идёт разом по всем арендаторам:
  поле стало необязательным (миграция `e013891656b9`).
- **uvicorn без `--reload`** перечитывает шаблоны, но не Python-код: правка роутера без
  перезапуска выглядит как «переменная не дошла до шаблона».
- Тест этапа 1 про UTM в теле статьи стал неверным (метки переехали в трекинг-ссылку) —
  заменён на два: с включённым и выключенным счётчиком кликов.

### Что не проверено вживую
Всё, что требует доступов Артура: создание настоящей пригласительной ссылки, приход апдейта
`chat_member`, ответы TGTrack. Первое, что нужно сделать после получения токена —
`python3 -m app.cli check-bot`.

## 2026-07-24 — Этап 3 (метрики площадок) СДЕЛАН

### Решение по способу сбора
Артур просил headless-браузер, который раз в неделю заходит в личные кабинеты Дзена и
vc.ru. Не делаем: от автопостинга отказались ради безопасности аккаунтов, а робот в ЛК
несёт тот же риск (Дзен-аккаунт = Яндекс-аккаунт с почтой и монетизацией), при этом
выгрузка отдаётся файлом в один клик. Взяли **импорт файла + ручной ввод**; Playwright
остаётся запасным вариантом, если выяснится, что выгрузки нет вовсе.

Файла от Артура ещё нет, поэтому парсер сделан терпимым к формату: сам определяет
кодировку (utf-8/utf-8-sig/cp1251) и разделитель, понимает «12 500» и «41,6%», читает
XLSX, угадывает колонки по синонимам. Что не угадалось — сопоставляется селектами в
интерфейсе. Порядок работы: загрузить с галочкой «только посмотреть» → увидеть отчёт →
поправить сопоставление → загрузить без галочки.

### Сделано
- `core/tables.py` — чтение CSV/XLSX, русские числа и проценты, даты и периоды,
  угадывание колонок.
- `services/metrics.py` — сопоставление строк со статьями (по ссылке на публикацию, иначе
  по нормализованному заголовку), срезы за день, dry-run, отчёт со списком несопоставленных.
  Дочитывания вычисляются из процента, если в файле только он.
- Уникальность `(article_id, collected_at, source)` (миграция `96280bb781b9`): повторная
  загрузка того же файла обновляет срез, а не задваивает.
- `services/reminders.py` + `scheduler/runner.py` (APScheduler): суточный добор меток из
  TGTrack и недельная проверка свежести статистики. Прогоны пишутся в `job_runs` и видны
  в интерфейсе; при заданном `NOTIFY_CHAT_ID` напоминание уходит в Telegram.
- Интерфейс: страница «Статистика» (загрузка, отчёт, сопоставление колонок, таблица по
  статьям), блок статистики и ручной ввод на странице статьи, колонки «Показы» и
  «Дочитывания» в списке, плашка «цифры устарели».
- CLI: `metrics-reminder`. В `docker-compose` добавлены профили `bot` и `scheduler`.
- **110 тестов** (было 83).

### Проверено вживую
Загрузка выгрузки: 3 строки → сопоставлено 2 (одна по ссылке, одна по заголовку), третья
показана как «не нашлось». Dry-run ничего не записал. Повторная загрузка того же файла —
0 добавлено, 2 обновлено. Второй срез за другую неделю дал прирост +6400 показов и
дочитываемость 42,9 % на странице статьи. Ручной ввод сохранился с источником «руками».

### Грабли
- **Старый процесс на порту**: после правок роутера сервер выдавал 404 на новые маршруты,
  потому что на 8099 висел прошлый uvicorn. Проверять `pkill` перед перезапуском.
- Проценты в выгрузках приходят и как «41,6%», и как «0,416» — второе без знака процента
  трактуем как долю и умножаем на 100.
- Период в колонке даты («01.07.2026 - 07.07.2026») берём по концу: срез описывает
  состояние на эту дату.

## 2026-07-24 — Визуальный разбор и правки интерфейса

Прошли по интерфейсу в браузере (Chrome DevTools), сверились с дизайн-скиллами и правками
Максима по ходу.

### Что переделано
- **Единая CSS-система** в `base.html`: холодная палитра, sticky-навигация с активным
  пунктом, иерархия кнопок, состояния фокуса, адаптив. Форматирование чисел и дат вынесено
  в `web/filters.py` (`ru_num`, `ru_money`, `ru_pct`, `ru_delta`, `ru_date`, `ru_plural`),
  повторяющаяся разметка — в `templates/_macros.html`. Инлайновые `style=` заменены утилитами.
- **Воронка переписана трижды**, и это стоило того:
  1) линейные бары — хвост (20 → 4 → 2 → 1) вырождался в одинаковые огрызки;
  2) доля от предыдущего шага — сломала монотонность: «2 заявки» оказались шире «4 подписок»;
  3) итог — цельный SVG-силуэт, логарифмическое сглаживание ширины, градиент одного
     оттенка, узкое место тонкой линией разрыва. Плюс раздел «Показать цифрами» с
     точными значениями, конверсиями и потерями.
- **Пороги узкого места** свои для каждого шага (`analytics.BENCHMARKS`): 40% с показов
  в дочитывания — норма, 0.7% с дочитываний в переходы — провал.
- **CTA в статье** теперь подписью, а не голым URL: ссылка с метками уезжала на три строки
  прямо в опубликованном тексте.

### Решение по библиотекам графиков
Plotly (`go.Funnel`) и ECharts рассматривались и отклонены: десятки мегабайт зависимостей
и JS-бандл ради одного графика на серверном Jinja-дашборде. Проблему разброса в пять
порядков библиотека всё равно не решает — она решается шкалой.

### Доступ к модели — через routerai.ru
По аналогии с ceramic и Vlad генерация идёт через OpenAI-совместимый прокси
(`ROUTER_API_KEY`, `ROUTER_BASE_URL`, `ROUTER_MODEL`); прямой ключ провайдера остался
запасным путём. Вся работа с моделью — в `integrations/llm.py`. Отдельно обрабатывается
402 «кончились деньги на ключе», а при любой ошибке статья собирается шаблоном и в
интерфейсе честно помечается как фолбэк (это поймал тест: раньше пометка не ставилась,
если ключ был роутерный).

**134 теста.**

### Подбор модели: сравнение 21 модели каталога
Прогнал через реальный промпт проекта 21 текстовую модель routerai.ru (Anthropic, OpenAI,
Google, DeepSeek, Kimi, Qwen, Mistral, GLM, MiniMax), судьёй сделал наш собственный
валидатор — он проверяет ровно требования Артура. Финалистов перепроверил на трёх темах,
и это перевернуло выводы: haiku, «чистая» на одной теме, на трёх выдала 39 баллов и каждый
раз вылезала за лимит Дзена (до 6023 символов при рамке 4000), kimi ушла в 7257.

Выбран **qwen/qwen-plus**: единственная уложилась в лимит во всех прогонах, минимальный
разброс, 0.15 ₽ за статью. Подробная таблица — в `_local_docs/work_reports/2026-07.md`.
Главный вывод: цена здесь не аргумент (0.15–7 ₽ за текст), выбирать надо по дисциплине,
и по одному прогону решать нельзя — разброс между темами больше разницы между моделями.

### Первая живая генерация (ключ RouterAI из проекта Vlad)
Модель `anthropic/claude-haiku-4.5` отработала: статья на 3983 символа, попала в голос
Артура (спокойный эксперт, цифры из его кейсов, без хайпа), уложилась в лимит Дзена.

Но валидатор сразу поймал слабое место: **ключевой запрос в текст не попал вовсе**
(плотность 0%). То есть haiku пишет прилично, а вот SEO-требование игнорирует. Варианты:
взять модель посильнее для длинных форматов либо ужесточить промпт по ключам. Решать
после первых боевых текстов — и это ровно тот случай, ради которого валидатор и писался:
проблема видна сразу, а не через месяц по отсутствию трафика.

## Этап 5 — развёртывание (24.07)

Сервис живёт на общем VPS в `/opt/projects/pokrushka`, репозиторий —
`github.com/Lamark860/pokrushka`. Работает: вход, дашборд, генерация, статьи, статистика —
все страницы отвечают 200, миграции прогнались с нуля, первый пользователь и контент-ДНК
засеяны. Появилось: `docker-compose.prod.yml`, `.env.prod.example`, `.dockerignore`,
GitHub Actions `deploy.yml`, `DEPLOY.md`.

### Репозиторий публичный — адрес сервера в него не пишем
В `DEPLOY.md` вместо адреса и пользователя стоят `<VPS_IP>` и `<VPS_USER>` (так же в tap18).
Реальные значения — только в `_local_docs/credentials/access-map.md`. Перед первым коммитом
прогнал поиск по всем попадающим в git файлам на ключи, токены и адрес сервера — чисто.

### Миграции отдельным контейнером, а не в команде запуска
Локально было `sh -c "alembic upgrade head && uvicorn …"`. На проде процессов три
(веб, бот, планировщик), и все три полезли бы мигрировать одновременно. Сделал одноразовый
сервис `migrate` с `depends_on: service_completed_successfully` — веб стартует только после
успешной миграции.

### Бот и планировщик подняты профилем `tracking`
Без токена бота и ключей TGTrack они бесполезны, поэтому по умолчанию не запускаются.
Workflow поднимает их сам, но только если соответствующие переменные в `.env.prod`
заполнены: в день, когда Артур пришлёт ключи, достаточно дописать их и пересобрать.

### Автодеплой лежит выключенным
Секреты `VPS_*` в репозитории не заведены: приватный ключ от сервера в GitHub кладёт
владелец, не я. Чтобы до этого момента каждый пуш не давал красный крест, первый шаг
workflow проверяет наличие секретов и при их отсутствии тихо пропускает деплой. Ровно то же
состояние у tap18 — файл есть, секреты не заданы, разворачивают руками.

### Домена нет, и это упирается в трекинг кликов
80 и 443 занял общий Traefik с Let's Encrypt, но выписывать сертификат не на что: свободного
домена под проект нет. Панель на голом HTTP терпима (внутренний инструмент), а вот ссылки
`/r/<code>` в опубликованной статье вели бы на `http://<IP>:8094/...` — читатель Дзена такое
видит и не жмёт. Поэтому до домена счётчик кликов у проекта держим выключенным: в статьи идут
прямые ссылки на канал. Когда домен появится — убрать `ports`, добавить сеть `proxy` и метки
Traefik, поправить `PUBLIC_BASE_URL`, включить счётчик.

### Следующий шаг
Остаток этапа 5: бэкап Postgres по расписанию (команда есть в `DEPLOY.md`, крона нет),
ротация логов, домен и HTTPS, журнал `job_runs` в интерфейсе. Всё остальное ждёт ответов
Артура — без токена бота и ключей TGTrack трекинг подписок стоит.

## 2026-07-26 — Дашборд: перевёрнутый диагноз, шаги вместо воронки, палитра

Полная схема экрана — `_local_docs/internal/architecture/dashboard.md`.

### Главное: воронка ставила ложный диагноз
Ступени меряются **разными приборами**, и приборы стоят не на всех статьях: показы и
дочитывания приходят выгрузкой площадки, переходы считает наш редирект, подписки — бот.
Расчёт складывал всё подряд: 20 кликов **одной** статьи делились на 10 080 дочитываний
**шести** → 0.2 % → «узкое место, чинить отсюда». На единственной статье, где измерены оба
конца шага, конверсия **2.27 % при ориентире 2 %**, то есть шаг здоровый. Система велела
чинить то, что работает.

Починено классом `Step`: каждый переход считается только по статьям, где измерены **оба**
конца, и показывает покрытие («по 1 из 6 статей»). `Funnel.ctr` — по тому же принципу.
Узкое место теперь `worst_step` — шаг с наибольшим отставанием от ориентира, а не первый по
порядку, не дотянувший до него.

### Силуэт воронки убран
`Funnel.shape/Segment/FunnelShape` удалены. Логарифмическое сглаживание ширины не
сглаживало, а **переворачивало акценты**: обвал в 99.8 % рисовался как «сузилось вдвое», а
`min_width` упирал три нижние ступени в одинаковую ширину. Улика была в самом коде — силуэт
прятался на мобиле через `display:none`, и страница ничего не теряла.

Вместо него шаги по отдельности, каждый в своём масштабе; рисуется единственная сравнимая
между шагами величина — отставание от ориентира, засечка ориентира на середине дорожки.

### Ноль ≠ «не измеряется»
`ArticleStats.has_metrics/has_links/is_empty`. В таблице вместо `0` в колонке «переходы»
стоит «не считается», если трекинг-ссылки нет. Статьи без единого измерения — под
раскрывашкой: сплошные нули посреди рабочих строк читаются как «система не работает».

### Новое: таймлайн
`timeline()` — накопительные показы **по датам выгрузок, а не по дням** (между выгрузками
про показы ничего не известно), на каждую дату берётся последнее значение по каждой статье.
Под линией полоса событий: подписки, заявки, продажи. Геометрия считается в сервисе
(`Timeline.plot()`), шаблон только рисует. Блок скрыт, если замеров меньше двух.

### Палитра — проверена, а не подобрана
Площадки `#2a78d6`/`#4a3aa7`/`#e87ba4` прогнаны валидатором палитр: худшая пара при
дальтонизме ΔE 13.0 при пороге 8. Статусные проверены по WCAG: деньги 3.35 крупным и 7.54
текстом, провал 6.51 и 5.85 на плашке. `--muted` был 3.69 при норме 4.5 — им набран весь

Доля площадок — полоса с сегментами, не бублик.

### Грабли этого этапа
- **Валидатор применён не туда.** Деньги и провал прогнаны через категориальную проверку
  → FAIL ΔE 4.1. Проверка не та: категориальная — для цветов, которые стоят рядом и
  различаются только оттенком. Статусные меряются контрастом по WCAG.

  съезжала на 18px и была короче соседней) и не срабатывал после сетки (следующий блок
  слипался). Ограничен прямыми детьми контейнера.
- **Форматирование денег утекло в сервис.** Вернул сумму числом: формат — в `web/filters.py`.
- Первая версия палитры была обесцвечена «ради одного акцента» — вердикт «серая и скудная».
