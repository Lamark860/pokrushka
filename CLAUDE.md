## Что делаем
Веб-сервис для канала **«База Маркетинг»** (заказчик — **Артур**, работаем по его правкам,
они ходят через пользователя): генерируем SEO-статьи и посты в голосе автора, Артур публикует
их **руками** копипастом, а система считает воронку показы → дочитывания → переходы →
подписки → заявки → продажи по каждому тексту.

Автопостинга нет и не будет — это решение Артура (копипаст = нет риска банов).

Проект вырос из полу-ручного MVP `~/projects/kotlowoi/traff/` (6 файлов на stdlib).
Тот каталог **оставлен нетронутым как референс** — исходная контент-ДНК, витрина дашборда
и расчёты воронки берутся оттуда.

## Стек и запуск
Python-моно: **FastAPI + Postgres + SQLAlchemy 2.0 + Alembic + Jinja**, зависимости в
`requirements.txt`, окружение — `.venv`. Postgres поднимается `docker compose up -d db`
(порт **5436**), веб слушает **8099**. Команды — в `README.md`.

## Раскладка
- `app/core/` — **ядро без веба и без ORM** (его легко тестировать):
  - `generator.py` — сборка промпта, вызов Claude, шаблон-фолбэк, CTA;
  - `formats.py` — профили площадок (лимиты символов, нужен ли подзаголовок и ключи);
  - `validator.py` — пост-проверка текста: длина, плотность ключей, правила Артура;
  - `markdown.py` — slug, снятие длинных тире, markdown → HTML;
  - `keywords.py` — разбор списка ключевых запросов (вставка и CSV);
  - `seed_knowledge.py` — стартовая контент-ДНК Артура (перенос `knowledge.py` из MVP);
  - `context.py` — мост ORM → чистое ядро (VoiceSpec/CaseSpec, UTM, CTA-ссылки).
- `app/services/` — сценарии, которым нужна БД: `links.py` (трекинг-ссылки статьи, CTA,
  отзыв), `subscribers.py` (апдейт `chat_member` → подписчик), `tgtrack_sync.py` (добор UTM),
  `metrics.py` (импорт выгрузок, срезы, дельты), `reminders.py` (свежесть статистики).
- `app/integrations/` — внешние API: `telegram.py` (Bot API), `tgtrack.py`.
- `app/bot/listener.py` — бот-слушатель событий вступления (отдельный процесс).
- `app/scheduler/runner.py` — расписание фоновых задач (отдельный процесс).
- `app/models/` — модели БД, `app/web/` — роутеры и шаблоны, `app/cli.py` — служебные команды.
- **Весь CSS — в `templates/base.html`**, форматирование чисел и дат — в `web/filters.py`,
  повторяющиеся блоки разметки — в `templates/_macros.html`. Инлайновые `style=` не плодим:
  для отступов есть утилиты (`.mt`, `.mt-s`, `.mb-0`, `.nowrap`, `.cell-narrow`).
- `migrations/` — Alembic. `tests/` — pytest. `_local_docs/` — приватная вики (не в git).

## Конвенции
- **Ядро не знает про ORM и HTTP.** Роутер собирает `VoiceSpec`/`CaseSpec` через
  `core/context.py` и передаёт в `core/generator.py`. Так генератор тестируется без БД.
- **Контент-ДНК живёт в БД, а не в коде.** `seed_knowledge.py` — только первичное наполнение;
  дальше Артур правит голос, кейсы и темник через интерфейс.
- **Значения по площадкам — в `formats.py`**, не разбросаны по коду. Добавляется площадка —
  добавляется запись в `FORMATS`.
- **Валидатор не блокирует, а сообщает.** Замечания сохраняются в `articles.warnings`
  и показываются рядом с текстом: решение — за Артуром.
- **`tenant_id` во всех таблицах данных** (задел на мультиарендность). Доступ к проекту и
  статье всегда фильтруется по `tenant_id` текущего пользователя — см. `web/deps.py`.
- **Модель зовём через `integrations/llm.py`**, а не напрямую из генератора. Основной путь —
  OpenAI-совместимый прокси **routerai.ru** (как в ceramic и Vlad: там team-ключ с контролем
  бюджета), запасной — прямой ключ провайдера, если роутерный не задан. Ответ ждём JSON
  (title/subtitle/body_md) и вытаскиваем его даже из ```json-обёртки.
- Без ключа `ANTHROPIC_API_KEY` система **обязана работать** на шаблоне-фолбэке: демо
  не должно ломаться от отсутствия интернета. Это покрыто тестами.

## Этапы
1. **Каркас** — готов: БД, генерация под 4 площадки, валидатор, ключевые слова, кнопки копирования.
2. **Трекинг подписок** — код готов, ждёт ключей Артура: инвайт-ссылки, редирект `/r/<code>`,
   бот-слушатель `chat_member`, TGTrack. Подробности — `_local_docs/internal/architecture/tracking.md`.
3. **Метрики площадок** — готово: импорт CSV/XLSX с угадыванием колонок, ручной ввод,
   срезы и приросты, недельное напоминание. Подробности —
   `_local_docs/internal/architecture/metrics.md`.
4. **Дашборд** — готово: воронка показы→дочитывания→переходы→подписки→заявки→продажи,
   CTR и конверсии, топ по взвешенным очкам, ручной учёт заявок со связкой по username,
   петля обучения (тексты лидеров идут в few-shot). amoCRM — только задел (поле `amo_lead_id`).
5. Деплой: VPS, Docker, Caddy, бэкапы.

## Грабли
- **`?start=` работает только у ботов.** Для канала атрибуция делается именованной
  пригласительной ссылкой (`createChatInviteLink`, `name` ≤ 32 символов), поэтому полный
  `utm_campaign` хранится в `tracking_links.utm`, а в имя ссылки кладётся короткий `code`.
- **Telegram Bot API не отдаёт список подписчиков.** Узнать, кто вступил, можно только из
  апдейта `chat_member` — нужен постоянно работающий бот-админ, cron не подходит.
- **API TGTrack требует, чтобы `user_id` мы уже знали** (методы `get_user_info`,
  `send_reach_goal`, `on_telegram_webhook`). Он дополняет свой бот-слушатель, а не заменяет его.
- **`metrics_snapshots` — это история, а не одна строка на статью.** В MVP таблица `metrics`
  имела `PRIMARY KEY article_id` и перезаписывалась; Артуру нужна динамика по неделям.
- **CTA дописывается после генерации** (`generator.attach_cta`): UTM содержит слаг, а слаг
  известен только после заголовка. Второй раз дёргать модель ради ссылок нельзя.
- **Код трекинг-ссылки подбирается ДО обращения к Bot API** — он же уходит в имя
  пригласительной ссылки. Если сгенерировать код дважды, атрибуция молча перестанет
  работать: в имени будет один код, в базе другой. Инвариант закрыт тестом в `test_links.py`.
- **Бот обязан быть админом канала**, иначе апдейты `chat_member` не приходят вообще и
  подписки не привязать. Проверка до подключения — `python3 -m app.cli check-bot`.
- **Логика атрибуции не зависит от aiogram**: `services/subscribers.py` принимает словарь
  апдейта, поэтому проверяется на фикстурах без бота и сети. Не тащить туда типы aiogram.
- **uvicorn без `--reload` перечитывает шаблоны, но не Python-код** — правка роутера без
  перезапуска выглядит как «переменная не дошла до шаблона». И проверяйте, что старый
  процесс на порту убит: иначе новые маршруты отдают 404.
- **Метрики хранятся срезами за день**, ключ `(article_id, collected_at, source)`. Импорт
  всегда идёт через `upsert_snapshot`, поэтому повторная загрузка того же файла обновляет
  строку, а не задваивает. Прирост — разница двух последних срезов.
- **Личные кабинеты Дзена и vc.ru роботом не парсим** (см. `architecture/metrics.md`):
  риск для Яндекс-аккаунта Артура выше пользы, а выгрузка отдаётся файлом.
- **Воронка считает показы по ПОСЛЕДНЕМУ срезу каждой статьи**, а не суммой всех срезов:
  иначе статья, померенная три недели подряд, утроит показы проекта.
- **Конверсия подписок к дочитываниям округляется до 2 знаков** — это доли процента,
  и при одном знаке все статьи выглядят как «0.0%».
- **Веса «очков» статьи** живут в `analytics.SCORE_WEIGHTS` — одно место на весь проект.
  Артур может их оспорить, это нормально: правим там.
- **Воронка рисуется воронкой** (SVG в `dashboard.html`, геометрия — `Funnel.shape()`):
  цельный силуэт с градиентом одного оттенка, ступени разделены волосяными линиями,
  узкое место помечено тонкой линией разрыва — не заливкой всей ступени. Ширина сглажена
  логарифмически: при разбросе в пять порядков точная пропорция схлопывает хвост в нить,
  а набор ярких трапеций читается как стопка кирпичей. Точные числа — рядом и в
  «Показать цифрами».
- **Библиотеку графиков не тянем.** Plotly (`go.Funnel`) и ECharts решают ту же задачу
  ценой десятков мегабайт зависимостей и JS-бандла на страницу; здесь один график,
  server-side Jinja и требование работать без интернета.
- **Порог «узкого места» свой для каждого шага** (`analytics.BENCHMARKS`): 40% с показов в
  дочитывания — норма, а 0.7% с дочитываний в переходы — провал. Единого числа тут нет.
- **Крупные цифры — пропорциональные, табличные — моноширинные.** `tabular-nums` на
  KPI-кегле выглядит разреженно; он нужен там, где числа выстраиваются в столбец.
- **CTA в статье — подписью, а не URL.** Ссылка с метками в теле текста уезжает на три
  строки прямо в опубликованном виде.
- **Тесты не ходят в сеть** — за это отвечает autouse-фикстура `offline_env` в
  `tests/conftest.py`: она зануляет ключи из `.env` и сбрасывает кэш настроек. Без неё
  веб-тесты начинают генерировать статьи через платный API (медленно, дорого, результат
  плавает). Заводите новый ключ — добавляйте его в этот список.
- **Один прогон тестов за раз**: тестовая база `traff_test` общая, два параллельных
  прогона роняют друг друга на пересоздании таблиц.
